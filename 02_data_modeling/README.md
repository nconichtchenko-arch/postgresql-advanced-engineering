# Моделирование данных: Data Vault, EAV и Битемпоральность

В данной работе рассматривается проектирование сложных моделей данных для хранилищ (DWH), выходящих за рамки классической схемы «Звезда».

## 1. Гибридная модель (EAV + Битемпоральность)
Для хранения динамических атрибутов ингредиентов пиццы была выбрана модель **EAV (Entity-Attribute-Value)**. Это позволяет добавлять новые атрибуты (например, «Аллергены») без изменения структуры таблиц.

Для отслеживания истории изменений сроков годности использована **битемпоральная модель**:
*   `valid_from` / `valid_to` — время, когда данные были актуальны в реальности.
*   `recorded_from` / `recorded_to` — время, когда запись была внесена в базу.

## 2. Модель Data Vault
Для связки сущностей (Посетители, Пиццерии, Посещения) использован паттерн **Data Vault**. Он обеспечивает масштабируемость и историчность данных:
*   **Хабы (Hubs):** Хранят уникальные бизнес-ключи (`Hub_Person`, `Hub_Pizzeria`).
*   **Спутники (Satellites):** Хранят атрибуты сущностей (`Sat_Person`, `Sat_Pizzeria`).
*   **Линки (Links):** Связывают хабы между собой (`Link_PersonVisits`).

## 📂 Файлы проекта
*   `data_vault_schema.sql` — DDL-скрипты для создания хабов, спутников и линков.
*   `eav_bitemporal_schema.sql` — DDL-скрипты для EAV-модели с битемпоральностью.
